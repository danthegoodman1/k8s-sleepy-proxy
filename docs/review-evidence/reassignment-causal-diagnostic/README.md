The [focused frozen-image reproduction](deployed-run.log) establishes the cause of this reproduced timeout. The first request for the untouched proof key connected in 0.648 ms, sent its request by 0.841 ms, received HTTP/1.0 200 headers by 11.077 ms, and received all 266 wire bytes—including the declared 81-byte body—by **11.402 ms**. The existing helper kept waiting in `read_to_end`. Its unchanged one-second outer deadline failed; the worker then returned `WouldBlock` at **1.012654 seconds**, with the complete frame still present. Both setup aliases likewise received complete bodies in under 15 ms but received EOF only around 1.01 seconds. This proves an EOF-dependent fixture failure, without assigning the delayed EOF to a particular network or proxy layer. It does not demonstrate a slow route subscription, backend setup failure, or stale cache result.
